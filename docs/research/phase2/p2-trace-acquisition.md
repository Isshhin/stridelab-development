# P2-F | Trace acquisition on development fixtures

The F3 summary adapter remains unchanged. A separate research probe can now reconstruct the registered 1,200-second window from a narrow TCX dialect plus independently recorded evidence. Only artificial bytes and artificial reference histories have been tested. There is no verified human/device combination, no eligible P2-B observation and no transfer of the probe's private QC output to P2-B. P2-B remains `P2_B_PROTOCOL_READY_DATA_NOT_READY`.

## Field-by-path matrix

V = `SUPPORTED_AND_VERIFIED` on **generated bytes only**; A = `SUPPORTED_NEEDS_REAL_DEVICE_AUDIT`; U = `UNSUPPORTED`; Q = `AMBIGUOUS_QUARANTINE`. The two TCX columns deliberately distinguish a tested implementation from a source-specific measurement claim. The separate experimental FIT reader has its own native capability boundary; the columns here describe the **registered window probe**, not all fields the file format can encode.

| Required input / output | Synthetic TCX v2 + independent reference | Same TCX device/firmware/export path, no pilot yet | FIT, registered window | GPX 1.1, registered window |
|---|---|---|---|---|
| Activity start, explicit clock, ordered sample times and observed intervals | V | A | U | U |
| Sample HR, zero/missing state, quarter coverage and gap flags | V | A | U | U |
| Trackpoint cumulative meters; calibrated footpod identity via separate reference | V | A | U | U |
| Single activity, lap and track; exact five quarter boundaries | V | A | U | Q for multiple segments; U otherwise |
| Registered first marker, device/firmware, sensor epoch and configured interval via reference | V | A | U | U |
| Complete independent timer transitions and segment timer duration | V via reference; U in TCX bytes | A via reference; U in TCX bytes | U | U |
| Unknown clock, changed sensor/epoch, reset, duplicate or contradictory reference | Q | Q | U | U |
| Pace inferred from summaries, power, moving time, environmental observations | U | U | U | U |

## What enters and what leaves

`p2_trace.decode(original_bytes, "tcx")` accepts standard TrainingCenterDatabase v2 with one Running Activity, child Id, one Lap with matching StartTime, one Track, and ordered, individually timed Trackpoints. It reads explicit DistanceMeters (m) and optional HeartRateBpm/Value (bpm), normalizes explicit offsets to UTC, and rejects wrong dialects, ambiguous cardinality, time reversals, duplicate samples, distance resets, corrupt numbers, unsupported extensions and incomplete tracks. Numeric zero distance at the beginning is valid; zero HR has no physiological weight. No coordinates, filenames or summary averages are returned. The original asset digest and returned trace are private. GPX gets no route reconstruction; multi-segment inputs are never flattened.

`acquisition_probe(trace, reference)` is an internal function **after** an admitted and linked source is established. Its inputs are trusted, immutable staging objects, not participant-supplied JSON or permission receipts. The reviewer binds the reference to the original digest, device epoch, firmware, prospective route card, calibration and configured sampling interval. Before inspecting probe output the reviewer must verify the registered route, marker, direction, easy warm-up, calibrated footpod basis (not GNSS), electrical chest strap, unchanged sensor inventory, units, absence of interruption or flagged artifacts, and complete timer event coverage of the window. TCX does not prove any of these facts itself. Lack of an independent timer/event record and segment-specific timer duration blocks this path even if all trackpoints look regular. A TCX lap duration or later recollection is insufficient. A pre-window pause/resume does not itself prove the warm-up complied with the card.

Select the first registered crossing 600–900 elapsed seconds after activity start. Never move the window to find better samples. Require observed distances at the start, each 300-second boundary, and end; this narrower footpod path performs no endpoint interpolation. Reject pauses or resumes inside that window, an inactive state at the start, a timer discrepancy over two seconds, missing configured interval, nonpositive quarter distance and any observed interval over five seconds. Each previous positive HR weights only the interval to its next observed point. Missing/zero HR has no weight. An interval to the next valid sample over five seconds across missing HR blocks; each quarter must have at least 285 valid seconds. Return the observed interval maximum, quarter valid seconds, time-weighted HR, distances and first marker offset for restricted comparison; no endpoint pairing, eligibility, pace adjustment or repeatability analysis.

Any failure keeps the item in the incoming/opportunity counts with its quarantine reason. The function raises an error and cannot maintain those counts itself. All authorization, account/ordinal verification, replay, withdrawal, downstream invalidation, context/effort and matched-repeat gates remain upstream or downstream responsibilities. Do not treat a QC pass, reference Boolean, byte digest or synthetic success as source admission, independent reconciliation or approval to issue a B0 segment. Unvalidated devices and dialects remain blocked, including most unreviewed XML extensions. Measured landmark interpolation, optical bridging, GPS sensitivity, multi-activity/multi-lap stitching, route inference and all FIT-to-B0 transfer remain outside this implementation.

## Reproduce

Run `python -m unittest discover -s research/validation -p test_p2_trace.py -v` from the research root (Python 3.12, standard library). The ten test methods exercise actual generated XML bytes, UTC rollover, zeros, missing HR and gaps, regular and irregular intervals, poor quarter coverage, boundaries, resets, timer start/stop/resume, sensor/epoch mismatch, duplicate/reversed timestamps, artifact and reference checks, corrupted/incomplete TCX, multiple GPX segments and unsupported format dispatch. FIT binary tests belong to the separate FIT investigation. For a future authorized path, use the blinded reference and independent device viewer procedure in [F3](p2-f3-parser-reconciliation.md) and preserve all disagreements. [B0](p2-b0-repeatability-protocol.md) remains the authority on the full protocol.
