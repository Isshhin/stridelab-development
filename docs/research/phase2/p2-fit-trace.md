# FIT trace feasibility: generated binary examples only

The F3 fixture checks session/lap summaries and verifies CRC and lap ownership through its pinned external decoder. This separate, dependency-free probe asks a narrower question: can the raw record and timer fields in a deliberately restricted FIT file be preserved with their session, units and timing? It does not replace F3, imply F3 reconciliation has run or release a B0 input. Use only project-generated bytes.

Source model: `inspect_fit(data, session_index=i)` returns the SHA-256 of the exact bytes, ordinal of the session message, UTC start/end, ordered record samples and a separate timer event stream. An explicit ordinal is required with multiple sessions. Session intervals are closed; touching or overlapping intervals and orphan records/timers quarantine the file. Source order is retained within each selected stream, and same-stream timestamp ties or reversals quarantine the selection.

| Binary evidence | Interpretation tested |
| --- | --- |
| Message 18: start_time and timestamp | UTC seconds since 1989-12-31; record/event must have exactly one session owner |
| Message 20: timestamp, heart_rate, distance | Absolute time, bpm and cumulative metres (wire value / 100); invalid sentinels become missing, zero stays zero |
| Message 21: timer start / stop / stop_all | State applies at the event time; after a stop, samples remain visible but inactive. Before first known event or with none, state is unknown. No state crosses a session boundary. |
| Header, data length, trailer | Reject bad header or file CRC, truncation, local messages without definitions, and unsupported compressed/developer headers |

Run `python -m unittest discover -s research/validation -p test_p2_fit_trace.py -v`. Fixtures are constructed in memory with a second CRC algorithm and both byte orders. Cases cover two separately selected sessions, a pause and restart, absent timer evidence, missing versus zero values, overlapping/touching sessions, orphan records, invalid selection, corruption, unsupported timer events and unordered timestamps.

**Decision: synthetic FIT record and timer extraction demonstrated; B0 ineligible.** The `b0_eligible` property always returns false. No pace or prediction is calculated. This subset intentionally does not interpret compressed timestamps, developer fields, session sport, distance resets, lap assignment, device/sensor identity or RR intervals. Fields outside the allowlist are discarded. File size is capped at 2 MiB; this is not a general FIT validator or importer. Native device agreement, correctness of timer events, sampling gaps, record distance behavior, per-athlete authorization, external reviewed linkage and independent segment QC remain unverified.
