# P2-F3 | Parser and reconciliation feasibility

**Synthetic fixture check passed. Real-device linkage performance remains unmeasured.** This workstream tests an account-scoped, manually adjudicated, single-purpose subset of F2.1. No study acquisition, held-out evaluation or policy execution took place. Architecture baseline `26a8331`. Wave 1 instructions read at `d2d8e4c`. F2.1 reviewed at `aa4e39a`.

## Reproduce the check

Use Python 3.12 with `fitdecode==0.11.0` and a source-only checkout of [the coaching lab at e255c5d](https://github.com/Isshhin/stridelab-coaching-lab/tree/e255c5d369af3576cc6ccfec44696ed4f15e1c35). Add its `src` directory to PYTHONPATH. In a writable temp environment run `python research/validation/p2_f3_fixture_check.py -v` from this branch. The command checks the LF-normalized SHA-256 of both upstream parser modules, generates FIT messages with a real CRC and XML files in temporary storage, invokes the original parser, and compares against the fixture author's fixed expected values. No external athlete fixtures or credentials are needed. Seven unittest methods passed locally on CPython 3.12.10, including parameterized negative cases. This run used the upstream decoder source at tag v0.11.0. The fixture suite is opt-in because the private lab source is an external prerequisite.

The research branch already has an attestation gate in `source_link_gate.py`, an immutable version contract in `revision_ledger.py` and an account/source ingestion ledger in `multiweek_reconciliation.py`. The F3 probe assumes the source registry, independent adjudication and accepted prescription snapshots have already crossed those trust boundaries. It does not authenticate arbitrary input, persist identity across processes, grant permission or implement the full F2 schema. Never use parsed filename/stem as an activity or athlete key. Raw parser results contain a local path and must remain in restricted staging.

## What the checks exercise

| Fixture or control | Expected result and condition for use |
|---|---|
| Two FIT sessions and two indexed laps | Ordinal 0 has 100 m, 60 s elapsed, 50 s timer, 130 bpm and 164 steps/min. Ordinal 1 has 90 m, 65 s elapsed, 45 s timer, and literal zero HR/cadence. Match laps by declared index range. Missing, overlapping or orphan lap indices quarantine the file in this subset. |
| Cadence 82 cycles/min with fractional component 0.5 | Running conversion gives 165 steps/min. Cycling receives no running conversion. TCX cadence remains its source channel until device/sport convention is known. |
| Duration, pace and power | Moving time is unavailable. GPX time is end minus start, TCX duration is sum of available lap TotalTimeSeconds with unverified pause semantics, FIT distinguishes timer and elapsed. Raw FIT 200 watts, 2 m/s and stationary 0 m/s decode in stated units; the adapter exports none of pace, power, moving time or speed. A zero speed has undefined reciprocal pace. Block analyses requiring these fields. Never relabel a zero HR as a valid physiological measurement. |
| TCX/GPX timezone rollover | TCX UTC+8 and GPX UTC−5 resolve to the same UTC instant across two local dates. Clock without an offset quarantines. This TCX fixture exercises the adapter's Activity Id attribute dialect; exporters using only standard child Id and Lap StartTime attribute need a separately verified bridge. |
| Malformed/corrupted/missing | Truncated FIT, missing indexed FIT lap, malformed XML, NaN or out-of-range HR, incomplete TCX lap, GPX segment gap, missing point timestamp or reversed time quarantine. Unknown intra-segment GPS gaps, TCX nested-summary ambiguity and plausible sensor corruption need source review. No sample-level measurements enter this probe's output accounting. |
| Reimport and cross-format duplicate | Identical reviewed source (account, digest, ordinal, format and first acquisition stamp) replays without another dose. Different serializations need separately reviewed edges to the same canonical activity. Preserve the first acquisition on repeat imports. Similar time, name or route never creates an edge. Contradictory aliases quarantine. |
| Late upload and reordered events | Before acquisition the activity is unavailable. Between acquisition and review it is unlinked. Replay with reversed input order yields identical counts. Keep accepted/effective prestart version; a later accepted backdated revision cannot replace it. |
| Partial and stale revision | Partial stays partial; never infer intolerance. Link to a superseded, ambiguous or unknown prestart prescription quarantines. |
| Cross-account source, wrong file ordinal, double assignment | Reject mismatched account before matching; ordinal substitution cannot be replayed against another parsed session. Conflicting targets quarantine. Multiple legitimate roles need F2 allocation and separate review, outside this subset. |
| Manual confirmation plus import | One reviewed bout; self-report separately retained. Manual-only claim has no measured dose. |
| Unplanned activity / no observed activity | No reviewed edge returns UNLINKED. An opportunity without evidence remains in the denominator with unknown performance. No skipped inference. |

**Measurement boundary.** A flattened GPX track can silently bridge segments in the upstream parser; the gate rejects multi-segment files. TCX lap sums can be incomplete and lap means unweighted; require complete explicit lap totals and an independent check before interpreting them. GPS-derived distance is rounded to 0.001 km in this adapter. FIT session summaries cannot establish steady intervals, environmental exposure or pause-free measurement windows. Matched-pace, power and sample-level B0 requests remain unsupported by this adapter until a separate trace-level implementation and manual audit exist.

## Independent manual reconciliation for a future authorized development pilot

1. The steward must first verify purpose, current permission, retention, withdrawal state, partition and account. Pin schema, parser, decoder, device/firmware, and the audit intake window. Keep the protected source immutable and separate from Git. Record the first import watermark, file digest, session ordinal and collection provenance privately. Permission uncertainty blocks intake.
2. Enumerate **every** in-scope plan opportunity, incoming original, declared activity, missing export and follow-up availability in the pilot window. Assign a stable audit ID, log rejected/quarantined items with reason and distinguish eligible, out-of-scope and missing. Audit all pilot rows, including zero-observation days. Keep opportunity and incoming-activity denominators separate.
3. Before seeing F3 output, a reviewer uses an independent device export viewer or separately decoded source records plus contemporaneous diary and version ledger to record expected owner, original/active plan and locks, actual occurrence, amount, unit, timer basis, lap/session indices, identity aliases, pause history, as-of acquisition and accepted/review times. Record manual-only and unknown explicitly. Never infer a planned match from nearby times alone.
4. A second reviewer compares the frozen reference to parser and reconciliation output. Compare identifiers, cardinality, ownership, version, missingness and eligibility exactly. Compare numeric values in native resolution and documented conversion (e.g. the half-unit rounding tolerance for nearest 0.001 km is 0.5 m). A channel lacking known source units, timestamp clock or resolution is unsupported. Record raw-versus-derived basis. Resolve disagreements through recorded source evidence, or retain quarantine. Never overwrite the original comparisons.
5. Replay after shuffled input and repeated imports at the same cutoff. Re-run before and after a late upload, retrospective edit or withdrawal and verify access rules before constructing the view. Log audit ID, parser/version, expected and observed, comparison, reason, resolution owner and date, superseding correction, time spent and remaining limitation. Keep raw traces, private hashes, credentials, local paths, notes and coordinates outside Git.

| Severity | Example and required response |
|---|---|
| Critical | Silent wrong link, another account's data, unauthorized use, double dose, hidden change to an accepted revision, lock violation or future-visible feature. Stop the affected path, isolate dependent products, investigate and independently replay before release. Any observed critical mismatch fails the path. |
| Quarantinable | Ambiguous match, conflicting source units, unknown timezone, broken or incomplete lap boundary, unsupported sensor, unresolved ownership. Withhold the observation or channel, preserve reason and denominator. Escalate to critical if it reached an eligible calculation. |
| Recoverable | Same reviewed file repeated; unstable display filename with unchanged proven identity; documented rounding within source resolution. Log and deduplicate or normalize; rerun idempotently. Changed bytes require adjudication, not silent replacement. |

Report correct eligible links / all audited eligible opportunities and, separately, correct source-to-actual identities / all audited incoming observations. Report unmatched, unknown, late, duplicate, rejected, quarantine, manual-only, partial and follow-up coverage separately. Stratify by device, firmware, format and parser version; report exact counts including zero denominators as unavailable, plus audit minutes per row. Freeze minimum useful coverage and burden by device with an independent reviewer before evaluation. No real-device denominator, useful margin or observed audit burden exists in this workstream. Unresolved input rights, absent predeclared margins, unsupported devices, insufficient coverage, or any critical mismatch block advancement for that purpose.
