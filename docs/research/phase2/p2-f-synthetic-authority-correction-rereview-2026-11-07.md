## Finding — P1: poisoned read can publish a chunk

`Broker.read` calls `next(chunks)` as part of `for chunk in chunks` before entering the publication `_state` block. A generator may execute arbitrary code at that point. In the reproduced case it performs a nested `read`, catches the inner `Denied`, and yields `must-not-publish`. The inner call sets `_violation=True`, but the publication block checks withdrawal, authority, inventory and data version **without checking `_violation`**; it appends the chunk, then the post-publication check raises `Denied`. `key.output` and `escaped` both contain the chunk even though the outer operation was poisoned before it was emitted. This violates the required same-owner fail-closed reentrancy/publication boundary. Source: `research/validation/p2f_private_custody.py`, the chunk loop and append; exact correction SHA was also fetched from GitHub.

Minimal safe correction for a subsequent synthetic-only task: check the reentrancy/violation state inside the same publication lock immediately before every append, and review all output paths and callback/iterator evaluation points. Add deterministic tests for a generator that performs and catches nested reads before its first yield and between later yields, both same-thread and unrelated-thread contention, withdrawal and exception interactions. Preserve already-emitted legitimate chunks exactly once and ensure later reads remain usable after a rejected operation. Do not imply that this resolves real broker, process, filesystem, or cryptographic security. No code correction was made in this review.

Reproduce: `py -3.12 research/validation/review_p2f_authority_correction.py`. Eight deterministic review-only schedules: seven pass and `test_nested_generator_cannot_publish` fails. The script is outside default `test_*.py` discovery and is intentionally failing until corrected. It also tests data rollback after release and between chunks, equal payload accounting, receipt before output, same-thread nested authorize and later recovery, other-thread contention, and re-raised `SystemExit`.
