# P2-F private development audit: blank working forms v1

Copy these forms **outside Git into the approved private environment**. A blank means not yet entered, never yes, zero, or a completed check. Enter a reason for each unavailable field. Use the [runbook](p2-f-pilot-runbook.md), [admission contract](p2-f4-human-feasibility-admission.md) and [custody contract](p2-f-private-custody-contract.md). Do not transfer a file or journal entry to fill the pre-intake forms. One participant, one authorized original, one diary entry, development only. Stop when any required precondition is unmet. The following headings are the execution order; rows may be repeated as specified.

### 1. Pre-intake checklist — steward, before inviting a transfer

Record the private evidence and check time separately for each: controller and role list ___; authorized isolated storage/disabled network sync and temporary storage ___; live suppression/partition registry ___; successful synthetic deletion/adverse restore and unrelated-account control on this staging setup ___; notice/withdrawal channel and deadlines ___; exact research commit, parser/schema, independent tool and clean synthetic checks ___; planned acquisition window and device/format scope ___; roster/cutoff, units and comparison rules ___; any missing check and stop reason ___. No private location or identity is specified by this template.

### 2. Participant choices — participant, before transfer

Complete the [participant-facing sheet](p2-f-participant-sheet.md) in private. Request separate yes/no decisions for original receipt/independent inspection including incidental fields ___; normalization ___; within-person audit derivatives ___; specified diary/plan linkage ___; development feasibility and tests ___; each optional diary field ___; notice version, participant confirmation/time and receipt locator ___. Decline or omission is never inferred consent. An optional no removes that field; a required no stops the proposed scope.

### 3. Steward decision — before intake

Make admission conditional on step 4 being in force; until both checks pass, leave the original at source. Recheck current grant before each operation including replay and close.

### 4. Pilot partition registration — before values

### 5. Original-file receipt — custodian

Verify grant; receive one direct original read-only, create scoped working copy only as authorized, compare private digests, and register the incoming observation even if parsing later fails. Record private source/receipt ID ___; original/working digest ___; source origin and exporter/version ___; device/firmware/sensor if known ___; received/first available/import watermark and offset ___; format and authorized incidental-content handling ___; separately authored diary/journal evidence and availability ___; approved original/work/normalized/derived locations and deletion dates ___; custody exceptions/disposition ___. Unexpected content or format: isolate without expanding inspection.

### 6. Blinded reference — reference reviewer

Seal information here **before harness exposure**. Roster entry for every offered opportunity: scoped opportunity ___; plan and revision available prestart ___; independent receipt/lock/choice ___; eligibility yes/no/unknown, reason ___; occurrence (including manual-only or unknown) ___; upload/late/context/follow-up status ___. Do not count a point or lap as a new incoming observation. A repeat import is a new observed attempt with a link to its first receipt, not another performed bout. Label deliberately injected replay/control attempts separately from the observational roster; do not inflate pilot coverage with them.

### 7. Harness comparison — operator then comparison reviewer

Operator records exact commit, interpreter, parser, schema, configuration and watermark ___; same authorized input digest ___; run start/end ___; current grant rechecked ___; reference seal verified before comparison ___. Reconcile **all** roster entries, including parser rejection, duplicates, reference unavailable and unexpected parser-only outputs. Use an outer comparison on scoped row keys, not just the intersection of successful outputs. Never silently align by nearest time. For historical assertions run the same recorded cutoff on shuffled input, then pre-/post-availability cutoffs on late material; separately record any trusted ordering at tied times. Before availability expect unknown, not retrospective knowledge. Use synthetic controls for events absent from the actual recording.

Keep missingness axis distinct from receipt, eligibility and quality: unknown; not asked/not collected; declined; absent in source; inapplicable; censored; withdrawn; unsupported; invalid. No upload does not establish no activity; manual-only occurrence has unknown numeric dose.
