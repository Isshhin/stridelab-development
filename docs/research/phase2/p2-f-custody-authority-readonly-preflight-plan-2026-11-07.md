## Private target freeze — mandatory before any target access

Maintain outside Git: machine identifier; Windows edition/build and architecture; target volume and filesystem; proposed service and interactive user principals and their identifiers; TPM manufacturer, model, firmware and version; Secure Boot and virtualization status; TBS availability; named observer; date, version and reviewer of target freeze; expected read paths/service names; evidence destination, retention and redaction; permissions and executable hashes. Record unknown values as unknown, not guesses. Before any target access, verify the record exists, is complete for the selected operations, and matches a separately approved target and operation list. Unknown facts that are themselves collection objectives must be explicitly marked as such, with target identity and all safety prerequisites otherwise complete. If not, STOP before target access. Do not commit identifiers or raw results.

## Evidence boundaries

Read-only enumeration could establish only identity/configuration, reported feature presence, and visibility of static metadata. It cannot establish NV definition or mutation, write-lock/delete semantics, persistence under mutation/power loss, nonrollback, non-equivocation, policy-delete usability, crash recovery or security of a live grant. No deadline-validity/retention claim is made; deadline-dependent authority stays disabled, so external trusted time is not required. No target evidence exists.

## Candidate operations — excluded pending independent side-effect review

Each candidate below has a precise API, but **none is approved for execution**. The provider must first verify behavior on the exact supported Windows release, required privileges, all indirect filesystem/registry/service/network/TPM effects, including auditing, telemetry, service activation and whether a read can persist state. Any unresolved persistence means exclude. Calls are individual API invocations, not a shell script or permission to write a helper. Evidence is privately captured by the named observer, redacted before publication; redact machine/user/domain/SID identifiers, paths, serials, asset tags, firmware identifiers and credentials. Cleanup: close handles and discard local memory only; do not delete or modify anything. Stop on unexpected access, request for elevation, failure, change of target, altered configuration, unknown effect, or requested network access.

No target command-line invocations, WMI providers, TPM command submissions, TBS context creation, service starts, registry enumeration, external connections, ACL mutation, temp file creation or cleanup deletion are included. TPM presence/version/manufacturer/firmware, TBS availability, Secure Boot and command-policy exposure may be listed as private-record unknowns, but **there is no approved or sufficiently specified operation here to query them**. Add exact independently reviewed API-level entries before seeking authorization for that wider scope. Public documentation review off-target is allowed independently and does not establish target facts.

The candidates above are not yet shown non-mutating even if documented as queries. OS access-time, auditing, provider caches and service activation are possible effects; a read-only intent is not proof of zero persistence. In particular, do not contact TPM or TBS merely to discover a property. Exclude any operation whose effects cannot be bounded and reviewed.

Explicitly forbidden: NV define/increment/write/lock/undefine, TPM clear/reset, key creation or policy/hierarchy changes, pilot keys, production account changes, authority transitions, participant/provider data and power interruption. Later destructive tests require a separate plan, disposable target and authorization. No cleanup should attempt to undo an unexpected mutation; stop and report instead.
