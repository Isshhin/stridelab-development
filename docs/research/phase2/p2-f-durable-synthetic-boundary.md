# Synthetic durable F2.2 store boundary

`research/validation/p2f_durable.py` is a research-only local SQLite journal for synthetic development fixtures. It is not a consent, authentication, encryption, device, or private-custody system. Do not store human records, provider data, keys, or held-out data here. The database and its backups are plaintext. The caller must supply a separately maintained current authority; `SyntheticAuthority` is only a test double. The caller must authenticate the actor and bind that identity to the requested view before invoking the store.

Every stored event requires the account and event identities, event schema, recorded/effective/available times, origin, view, purpose grant, partition, lineage class and data. Optional supersession must resolve within the same account and scope. Only synthetic development events are admitted. Schema 2 and 3 carry this full envelope; replay normalizes their explicit marker without rewriting events. The older unscoped prototype database and incomplete historical events are rejected rather than assigned missing metadata. Their missing values require independent evidence, not migration defaults.

Decision-time projection selects only the authorized account/view/grant/partition and filters on availability and optional append watermark. Current projection applies known corrections and link revocations by the supplied current time to the historical selection. Scope checks precede payload reads and are repeated before returning values. The authority remains outside backups; withdrawal or grant revocation therefore also blocks access after reopening a backup. Callers must check `assert_current` before reusing a projection. Values already copied out into Python objects cannot be recalled. A revoked scope also blocks account-wide append validation and backup until a trusted authority permits all affected scopes; this is a conservative fail-closed limitation.

The version 1 projector is separately frozen in `research/validation/p2f_projector_v1.py`; changes to the current projector must not alter that file. Both projectors retain original event identities and digest the complete selected envelopes. The store uses SQLite immediate write transactions, immutable-event triggers, full synchronous writes and an account generation to reject stale writers; an identical retry is idempotent. Crash tests include process termination before commit. Correction conservatively invalidates all links for its affected activity because the reference model does not record source-level link dependencies. Distinct source aliases require explicit adjudication; conflicting fields remain conflicts. Event and invalidation IDs and counts are returned as lineage.

The source-adapter boundary must supply trusted identity, the actor/view and its availability evidence, purpose and partition grant, lineage, and explicit adjudications. It must never infer authorization or identity from source bytes. No real-device, private-pilot, Gate 2, P2-B, or coaching-effectiveness claim follows from these tests. Current authority checks are not an atomic revocation protocol across a separate real authority, and a real custody implementation would require independent review, secure storage, key management, authenticated principals and restore/deletion evidence.

Status: synthetic software feasibility only; `P2_F_GATE_2_NOT_READY`; `P2_B_PROTOCOL_READY_DATA_NOT_READY`.

## Projector 3 correction and replay limits

Projector `3` is the default for newly requested projections. It derives each opportunity's activity membership from surviving links, so distinct links remain in lineage while one activity appears once. Partial revocation keeps the membership while a link remains; complete revocation or source correction removes it. Existing event journals are replayed without mutation. Projectors `1` and `2` retain their prior results, including their known duplicate-membership defect, and must not be treated as current-validity counts. Version 1's pinned file remains unchanged. Projector 2 is historical behavior in the current source, not a separately frozen implementation.

Projector 3 exposes the selected watermark, journal event order and a journal-sequence digest in addition to the event-set digest. Because the store does not establish a trusted actor-side sequence, it conservatively quarantines any equal-availability events in the relevant view; unrelated simultaneous events can therefore also be rejected. It quarantines uninterpreted `supersedes_event_id` history, source corrections available no later than their predecessor, and revocations available no later than their link or effective before it. Decision-time checks stop at the historical cutoff and watermark; current-validity checks include applicable later invalidations. These are fail-closed boundaries, not complete general supersession or causal adjudication. Projector 3 depends on the current reference projector and is not separately pinned for future versions.

Backup now creates a previously nonexistent destination exclusively and refuses an existing path. A failed or interrupted backup may leave a partial new destination; do not treat it as a valid restore until independently checked. The plaintext synthetic copy and its authority remain unsuitable for private records. A successful test of the synthetic reopen and external suppression barrier is not a private custody drill.

The standalone in-memory `p2f_foundation.FoundationLedger` remains a historical reference and still appends one activity ID per link. Only durable projector 3 supplies the corrected membership behavior.

## Independent follow-up: replay boundary and concurrent validity

The durable wrapper now owns its identity, timestamp and digest helpers rather than calling mutable reference helpers during pinned replay. Current validity also repeats the authority snapshot after checking the journal head. These checks do not form an atomic cross-system barrier: a synthetic writer can append during that final authority check and the method can return an older generation without detecting the append. The regression test records this as an expected failure. Do not treat the validity check as a complete concurrent-change guarantee. The caller must retain the authority and invalidation inputs separately; the in-memory test double cannot survive process recreation or enforce private withdrawal.

## Independent follow-up: activity chronology

Projector 3 can expose an activity end after its stated availability. Projector 4 is the default and quarantines a visible activity whose end is later than its availability; earlier projector results remain unchanged. This is a narrow synthetic guard, not verification of provider timestamps or all observation types. Projectors 3 and 4 still depend on mutable reference code and are not independently pinned. Their version labels alone do not guarantee future replay stability; synthetic durability remains blocked pending a separately pinned replay boundary and reproducible current-validity inputs.

## Synthetic current-validity consistency barrier — 2026-11-07

The prior head/authority/head style checks allowed a journal writer to commit during the final authority check. Current-validity replay for all projector versions and later `assert_current` checks now use a fail-closed final barrier: acquire a SQLite `BEGIN IMMEDIATE` writer reservation without waiting or retrying, then acquire the shared `SyntheticAuthority` guard without waiting, verify journal generation and authority snapshot, and construct the returned projection while both are held. The protected validation is the operation's linearization point. A competing SQLite writer waits until the reservation is released; an already reserved journal fails immediately with `journal busy during replay`, and a contended authority guard fails with `authority busy during replay`. Reentrant journal or authority writes on the validating thread fail closed. Lock order is journal reservation before authority guard. Historical decision replay remains unchanged.

The previously expected-failure regression is now a normal test. Additional synthetic tests cover final-window journal and authority mutation, both changes, repeated fail-closed writes, already-reserved journal, process and thread writers, withdrawal contention, absence of deadlock, stable replay, metadata, and reopening. These tests establish a bounded synthetic, process-local authority protocol only: all relevant authority mutations must go through the same guarded `SyntheticAuthority` instance. The authority is not durable or shared across processes and is not a nonrollback authority. The journal lock is cross-process SQLite locking, but it does not turn the authority into a cross-process service. No lock can recall a projection after its protected linearization point; callers must use `assert_current` before later reuse. Real custody would require a separately designed and independently reviewed cross-system consistency protocol. Independent Work review is still required before a final synthetic-durability verdict.
