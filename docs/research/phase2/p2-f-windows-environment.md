# Private pilot on Windows: setup and acceptance

The custodian completes a private copy of this procedure on the intended machine **with invented data before asking for approval**. Begin every control at **UNKNOWN**. **CONFIGURED** means a setting or boundary was applied. **VERIFIED** requires a dated observation or synthetic challenge on that machine, build, account and tool version. A failed challenge stays UNKNOWN with the failure recorded and intake blocked. Repeat affected checks after any change. Keep actual paths, account names, keys, identifiers, screen captures and detailed logs private.

1. Choose a dedicated offline Windows profile and local NTFS volume outside repositories, sync roots, shared folders and redirected known folders. Include the operating-system/profile volume if it holds paging, hibernation or caches. Before staging anything, have the custodian verify each volume's encryption is complete and protection on. In the private console, use `manage-bde -status <drive>` for each chosen drive, or have the authorized administrator verify equivalent evidence. Check recovery-key custody and who can unlock the volume. Record status only. Do not print recovery keys. Unknown protection or unapproved recovery access blocks use. [Microsoft volume-status reference](https://learn.microsoft.com/windows-server/administration/windows-commands/manage-bde-status)
2. Choose actual locations privately. On an empty root, use Properties → Security → Advanced to review inheritance and assign role groups before adding files. Retain authorized system/administrative recovery where required and disclose privileged access. Reject shared administrator credentials, broad inherited read/write, network/mapped roots and junctions/symlinks to other locations. Operate as standard users. Use a separate custodian or authorized administrator for controls that require elevation. Do not alter system-wide controls on a shared machine.
3. Create the following **logical areas**, substituting privately chosen locations. Test access from the actual standard-user roles, including denied access through an ordinary file-open dialog. A read-only file attribute is insufficient: verify the parser and reviewer cannot overwrite, rename, delete or replace the synthetic original through its parent directory. Verify comparison reviewers cannot write frozen references. Overlapping roles must be documented with the resulting independence limitations. [Custody roles and rules](p2-f-private-custody-contract.md)

| Area | Minimum authorized use |
|---|---|
| identity-and-consent | Steward and designated custodian. Keep receipt and identity map apart from processing. |
| immutable-original | Custodian imports once. Reference reviewer and authorized input reader can read only. |
| working, temporary, quarantine | Isolated per run. Custodian and assigned operator only. Quarantine denies normal processing. |
| normalized, linkage, trace | Operator writes scoped outputs, comparator reads only the agreed projections. |
| independent-reference | Reference reviewer writes before comparison. Freeze access and integrity before releasing a read-only copy. |
| comparison, audit-log | Comparison reviewer records discrepancies. Custodian restricts and inventories evidence. No external log forwarding. |
| current suppression/exclusion authority | Custodian controls separately from working state and its backup. Verify a restored stale authority cannot replace the current one. |

4. Configure and then challenge each exposure path below. Use a distinct, invented filename and marker for this rehearsal. Where practical compare private before/after inventories under the dedicated profile. Use normal tool close, forced termination of a synthetic run and restart. Check named locations privately without searching other users' files. Where a managed policy, opaque cache, queue or monitor prevents verification, record UNKNOWN and use another approved environment.

| Path | Configure privately | Verify with synthetic input |
|---|---|---|
| Sync and outbound access | Inspect OneDrive Settings → Sync and backup → Manage backup and other sync clients, mapped drives and redirections. Keep staging outside them. Isolate pilot tools from network including crash/telemetry helpers. | Resolve root and parents, confirm no redirect or overlapping sync policy. Verify outbound isolation and inspect local pending queues/logs after normal and failed runs. A paused sync client or momentary disconnect cannot establish persistent isolation. Do not reconnect a profile with unreviewed queues. [OneDrive backup](https://support.microsoft.com/en-us/onedrive/back-up-your-folders-with-onedrive) |
| Windows Search | In Settings → Privacy & security → Searching Windows / Advanced indexing options, exclude the staging location from applicable classic/enhanced indexing. | Inspect effective included locations. After the index updates, search by unique synthetic marker from Windows Search outside the root. Use a separate synthetic indexed control to show the search works. Direct folder enumeration is not an index test. [Search configuration](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/find-your-files-and-apps-in-windows) |
| Previews, histories and capture | In the pilot profile turn off Explorer Preview and Details panes, enable icons-only display and disable recent items. Disable viewer MRU/recovery, screen capture/Recall where present, clipboard history/sync and IDE shell transcription. Use neutral names. | Open/close synthetic input with the actual viewer and parser. Reopen Explorer Home, recent items/jump lists, viewer history, recovery and thumbnail caches. Compare inventories for new entries; unknown opaque residue requires a contained profile or alternate viewer. |
| Crash reporting, telemetry | Review tool-specific diagnostic options, effective Windows Error Reporting/local dump settings and queues. Use offline tools and approved private temp/dump locations or prevent collection. | Exercise handled malformed input and a supervised synthetic forced close. Inspect actual report queue, dump and tool log destinations. Forced close cannot prove every native crash path: verify effective policy for unexercised routes or keep UNKNOWN. [Local dumps](https://learn.microsoft.com/en-us/windows/win32/wer/collecting-user-mode-dumps) · [WER policies](https://learn.microsoft.com/en-us/troubleshoot/windows-client/system-management-components/windows-error-reporting-diagnostics-enablement-guidance) |
| Temp, caches, recycle and app recovery | Launch tools with per-process TEMP/TMP pointing into controlled temporary space. Inventory viewer/parser autosave, OS temp, application cache, shell history, recycle behavior and any external monitoring. | Close/restart tools and check scoped temp, profile temp, tool data, recycle bin and history using the synthetic marker/inventory. Test the exact chosen removal method on one invented file and check for restoration. Never empty a shared recycle bin or clear another user's history. |
| Antivirus/EDR | Keep protection enabled. Have the authorized security owner identify scan, quarantine, cloud submission, sample retention and queued upload rules. Do not add broad exclusions or submit a pilot file to test policy. | Confirm effective policy and offline containment, inspect relevant local queues/quarantine using synthetic rehearsal. If evidence cannot rule out an unapproved transfer or retained sample, use a different approved staging machine. [Defender cloud sample-submission policy](https://learn.microsoft.com/en-us/windows/security/threat-protection/windows-defender-antivirus/enable-cloud-protection-windows-defender-antivirus) |
| Backup and restore | Inventory File History, Previous Versions/shadow copies, volume images, enterprise agents, external media and restore scratch. Choose verified exclusion or an approved protected backup with access restrictions and a dated expiry. | For each actual backup mechanism, verify effective scope against a completed synthetic backup/catalog. For included stores, restore only invented material under closed access and challenge stale aliases, derivatives, late import and unrelated-account survival. If backups excluded, use a stale working-state copy for the challenge and verify exclusion separately. |

5. For each row privately record control, actual scope, operator, OS/tool version, setting, evidence, date, state, open issue and resolution owner. Revoke access and close the pilot workspace after rehearsal. Apply the deletion checks below. Intake requires VERIFIED for every applicable safety boundary, a successful actual-machine restore/deletion rehearsal and a separate steward decision after explicit approval. Record why any unavailable product/feature was verified absent. A repository test cannot certify the host.
