# F5 · Bounded pilot linkage implementation

**Usable for synthetic replay and a separately admitted, privately supervised development exercise.** F2.1-pilot.2 is a one-opportunity research adapter of [F2.1](p2-f2-linkage-contract.md), not a production ledger or a validation of real device identity. Session G remains frozen at 26a8331. No pilot grant, signer, sample, or empirical coverage is supplied.

| F2.1 requirement | Bounded implementation / exclusion |
|---|---|
| Account, athlete, split and purpose | One isolated in-memory ledger per exact account, study pseudonym, purpose grant, development-pilot partition and deciding view. The caller cannot select an entity across scope. Supply mappings only after private F1/F4 admission. Unknown owners/connections or partitions fail closed. |
| Plan, version, opportunity, accepted revision | Initial plan and opportunity retain identity. Applied revisions carry immutable intent, parent revision, expected parent version and a new version ID. Manual edits use their own event; an accepted offer checks decision, exact offered intent, active revision and lock together. Stale/locked/competing branches cannot yield a projection. |
| Decision, choice, receipt | A contemporaneous decision has an explicit view watermark, exact input IDs/hash and one offered option or no offer. Rejection and dismissal preserve the plan. Prestart resolution requires a separately journaled receipt for the latest version available before starting. An unordered start-time receipt/version is indeterminate. A backdated change arriving later cannot rewrite delivery. |
| Performed activity and source observation | Keep actual start/end with offset, recorded/effective/available times and device import time distinct. Trusted connection + namespace + external identity + format resolves to a steward-reviewed canonical activity in this scope. Repeated identical imports count once. Independently mapped FIT and TCX aliases may support one bout. Changed bytes require the prior event, both digests, reason and private correction approval. Changes invalidate current derived links; fresh evidence is needed. Identical bytes assigned to different bouts are quarantined. |
| Missingness, context, follow-up | A matched declaration of occurrence can exist without a file; numeric dose stays null/not_collected. A file without a plan remains unmatched. No evidence for an opportunity means unknown. Context targets a prior event; reported, withheld, unknown and not_collected remain distinct. A missing follow-up window is unknown. A registered window yields not_due, awaiting or overdue_missing; a censor event or independent, in-window observation yields censored or observed only after availability. No endpoint values, success labels or inferred subjective scores. |
| Link, revocation and withdrawals | A separate attestor mapping binds its evidence ID to bout, opportunity and delivered revision. The one-to-one pilot rejects second edges/splits. Edge revocation preserves the opportunity and bout but clears the match. Grant withdrawal clears the entire in-memory account ledger, private mappings and derived access; later import and even past replay fail. Other account ledgers are independent. |
| Historical replay | Offset-aware clocks normalized to UTC for ordering. Live custody authority checked before every read and write. A historical cutoff is exclusive by default; at the exact cutoff only a supplied trusted watermark can include ordered events. Reorder input freely; conflicting IDs, bad chronology/ancestry, nonmonotonic sequence or unresolved concurrent peers quarantine the projection. Decision input digest remains separate from the later snapshot digest and link/follow-up state. |

**Private operating boundary.** [Implementation](../../../research/validation/p2f_linkage.py) is an importable standard-library module. The steward authenticates the account, grant, view journal, origin, manual declarations, prestart receipts, equivalence/correction and link reviews *before* constructing the ledger; a source file must never populate its own trusted registry. The adapter accepts trusted journal events, not arbitrary client assertions. Use separate private registries and isolated ledger instances per scope. No hosted custody, signatures, clock verification, automatic duplicate discovery or identity enrollment are provided. Uncertain cross-format equivalence must be left unmapped, not declared to be two separate bouts. No synthesis of missing IDs, times or activity intervals.

Call `append(scope, rows)` then `replay(scope, cutoff[, watermark])`. Append stages immutable copies; a successful append alone never means a match. Only a successful replay returns a projection. Catch `Quarantine` at the workflow boundary and record the excluded attempt/reason for denominator and burden accounting; never export a partial result or fall back to an earlier snapshot. Digest inputs and projections remain private. Recheck the current grant at access time; never resurrect a withdrawn instance from backup. External copies, references, backups, receipts and derivative deletion remain the steward's F4 responsibility, including invalidation of previously returned in-memory or saved results.

**Intentionally narrower than F2.1.** One trusted view per reconstruction; offline capture can remain invisible until sync but the harness does not reconcile two competing device journals. One opportunity per plan, one active link per opportunity/bout, native intent token only, single-option choices. No future-effective scheduling, scheduled windows/zone model, full prescription/dose/steps, many-to-many exposure, revision merge, cancellation, lock overrides, expiry, candidate policy or unshown counterfactual analysis. Unknown/declined fields and denominator presence are retained; no measure of completion, reference endpoint, dose estimate, B0 pairing, quality adjudication or population outcome is calculated. Full source/device metadata and protected hashes belong in the restricted F3 audit. The adapter cannot adjudicate two conflicting sources, manufacture an independent reference or certify physical deletion. Any unsupported case is excluded from the bounded path.

**Verification.** [Synthetic tests](../../../research/validation/test_p2f_linkage.py) include wrong/unknown scope, wrong partition, independent edge evidence, alternate formats and collisions, retained original and later correction views, scope withdrawal followed by re-import, unaffected second account, manual-only performance, explicit rejection and accepted choice, lock/stale/future changes, late backdated revision, reordered input, same-time ties/watermarks, late upload and offset rollover, declined context, missing/censored/late independently observed follow-up and revoked link. Run from repository root:

```sh
python -m unittest discover -s research/validation -p test_p2f_linkage.py
```

## Private authority and recovery amendment

**Current right to access and historical as-of time are different clocks.** Before constructing any ledger, the custodian checks live private admission, partition, permitted purposes, capture window, reviewer mappings and exclusions. The new required `authority=` argument supplies the independent grant interval, current trusted clock, suppression register and committed journal head. Registration is a steward operation, never evidence of consent by itself. Grant start is inclusive; expiry is exclusive. Missing grant, unavailable clock, early/expired/revoked grant, future available event, replay after the current instant, stale working head or foreign scope blocks access. Suppression can be applied outside the ledger and takes effect across all sessions. All supported access is development-only; the adapter has no sealed/confirmatory import operation.

Use only steward-resolved aliases. Bind every verified new alias to the same scoped identity; collisions and unmapped aliases are denied. A known alias or suppressed identity cannot be re-enrolled under a replacement grant in this bounded adapter. Duplicate formats and corrected versions are never a fresh eligibility unit. Truly unknown real-world aliases require independent identity review; this program cannot discover them. Source, worksheet and derived outputs inherit the same scope and exclusion.

**Restore boundary.** The custodian supplies current authoritative governance and a trusted non-rollback clock independently of working backups. Do not pickle, restore, copy, or regenerate a grant registry from participant rows. `checkpoint` supplies rows only. Open an isolated ledger then call `restore(scope, load_rows)`: it checks rights before invoking the opener, checks the digest against the independent current head, then rechecks authority before making rows available. A stale but previously valid working copy cannot replace a newer one. Direct reads, replays, re-imports and derivative access after external revocation all fail. The current-authority implementation is in-memory, single-writer and not crash-safe; **a newly created empty process is not a recovery authority**. The steward must re-establish current custody/suppression and journal heads independently, or abstain from restoring or processing. Persistent backups, caches, returned values, authenticated administration and physical erasure require private operational controls; these tests do not establish secure deletion.

**Versioned audit.** [AuditSeries](../../../research/validation/p2f_linkage_audit.py) is the current-result gate for one reviewed source/edge per grant. Use `pin` with an independently frozen private worksheet, current source event, verified edge and immutable parser/implementation pin. Configure a trusted offline runner for that exact implementation; do not substitute a mutable name such as “latest”. Supply the original and worksheet bytes to `compare`; it checks both protected digests, historical input IDs and snapshot before executing the runner. A material format/comparison failure returns quarantine; unexpected tool crashes interrupt the run and must be investigated. A runner returning private trace QC is evidence of execution only; a reviewer must separately adjudicate the discrepancies. Do not treat a bare low-level probe output as the currently accepted audit.

Any journal change, corrected export, revoked link or parser/reference pin change makes the prior result ineligible as current until a fresh pin and successful comparison; do not substitute an older successful result after quarantine. Use `current()` to obtain active metadata. Reproduce a previous comparison only by explicit version with its original bytes, exact worksheet, retained runner and historical event set, under a still-active grant. The old result remains historical; a different output for the same version raises a mismatch and disputes that version. The ledger never makes withdrawn outputs available merely to demonstrate reproducibility. Record operational reviewer identities, version binaries, discrepancies and actual audit burden privately; printed hashes and aliases do not belong in Git.
