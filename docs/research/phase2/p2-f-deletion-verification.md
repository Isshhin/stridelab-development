# P2-F | Verify each private copy after withdrawal or close

The custodian rehearses this on invented accounts A and B on the proposed Windows configuration. In the eventual admitted pilot, apply the approved deadlines and scope to pilot-controlled copies only. Keep identifiers, absolute paths, location inventories and completed evidence privately. The participant's source device is outside this procedure.

| State | Required evidence |
|---|---|
| VERIFIED_DELETED | The object previously existed at this specific logical location, an authorized removal occurred, and a separate inventory/read check with sufficient access confirms absence after closing and reopening the store. |
| ACCESS_REVOKED_PENDING_BACKUP_EXPIRY | A known backup copy remains under approved retention. Confirm ordinary access and ordinary restore are blocked, controlled restore enforces current withdrawal before exposure, and an accountable verifier has an absolute expiry date. Recheck the catalog at expiry. |
| SUPPRESSED_FROM_PROCESSING | A known retained object or minimum suppression record exists under disclosed authority. Verify active reads, replay, processing and exports of participant content are blocked. Record purpose, permitted access and retention. |
| NOT_PRESENT | No object was ever produced in a named, inventoried location, established by the creation ledger and bounded inspection. For example, a verified unsupported channel produced no segment. Absence at one location says nothing about copies elsewhere. |
| UNVERIFIED | Evidence is missing, access for verification is insufficient, the expected state is ambiguous or the verification method cannot inspect the relevant store. An empty search, denied read or missing filename alone cannot establish deletion. |
| DELETION_FAILED | A required removal returned a confirmed failure, a supposedly removed item is present, an expired backup persists, or a supposedly revoked item becomes readable or processable. Block the affected path, keep the failure in the log and independently retest after correction. |

**Sequence.** Revoke the current grant first and suspend all processing. Freeze the inventory of scoped aliases and descendants, affected stores, deadlines, expected state and verifier. Close programs to release handles. The custodian removes **only** registered pilot-controlled items through the relevant store interface. Resolve the actual path privately and check its parent is inside the intended controlled area, with no reparse-point escape, before each file action. Never search for and delete by wildcard, empty a system recycle bin or remove a whole shared cache. If safe targeting is impossible, isolate access and report the observed state. An independent verifier or second pass reopens stores with enough permission to see existing objects and checks ordinary access separately.

| Private inventory entry | Path-specific manual check |
|---|---|
| Original export and agreed diary | Inventory read-only intake and any controlled transfer staging. After targeted removal, re-open both areas as custodian, check inventory and direct scoped lookup. Verify removal did not leave a recoverable recycle-bin copy. |
| Working copy | Check operator run directory, retry/correction subdirectories, import inbox and quarantine for all registered aliases. Verify the operator cannot reopen by known path or recent-file history. |
| Normalized representation | Query the reopened active store and any per-run serialized rows and versioned materializations by account, recording family and correction lineage. |
| Linkage record | Query edges from both the opportunity/revision and activity/source sides. Preserve unrelated opportunities as appropriate. Confirm no stale edge reappears under a corrected alias. |
| Trace and segment | Check point store, segmented extracts, cached windows and export spool separately. Reopen each index and attempt a stale segment lookup or replay. |
| Derived measurement | Check computed rows, summary/aggregate caches and affected exports. Rebuild eligible summaries under the current grant view and verify no withdrawn contribution returns. |
| Independent reference | Reference reviewer inventories frozen original worksheet, draft copies, viewer exports, revision history and recovery copies. Verify each after the reviewer closes and restarts the tool. |
| Comparison and audit worksheet | Check comparison rows, discrepancy/adjudication history, time log, worksheets and their exports. Keep only specifically allowed non-identifying process evidence or approved minimum restricted audit state, each with its own disposition. |
| Temporary file | Check controlled per-run temporary area, process TEMP/TMP, actual profile fallback and parser/viewer autosave after normal close, failed run and restart in rehearsal. Inspect Recycle Bin for the scoped token. |
| Application cache | Check identified parser/viewer cache, recent/jump list, preview/thumbnail, recovery, dump and diagnostic queue via custodian-approved inspection. If a shared opaque store cannot be inspected or safely purged, isolate it and mark UNVERIFIED. |
| Stale snapshot and restore scratch | Inventory snapshot store, local shadow copies, database snapshots/journals and every controlled restoration copy. Verify each separately, including temp/cache generated by the restore viewer. Run the adverse restore challenge below. |
| Backup | Inspect each agreed backup catalog/generation, off-machine destination and retained rotation under the named custodian. Check access controls and independently verify scheduled expiry. If demonstrably excluded from that backup from inception, record NOT_PRESENT for that backup only. |
| Suppression and exclusion | Verify minimum authorized private denial/partition state persists outside restored snapshots, including identity aliases and corrected exports. At its own expiry follow the agreed deletion policy and default-deny unresolved identities. No legacy alias or segment can become confirmatory eligible. |

**Adverse restore.** With only invented accounts, restore pre-revocation bytes in isolated scratch with processing and ordinary access closed. Make the current authority unavailable and verify the reader refuses to open. Reconnect only the current authority, reject stale authority, enforce A's withdrawal, and verify A's raw, normalized, linkage, old alias, corrected/re-exported alias and derived views are inaccessible. Attempt late re-import and synthetic split selection. Check B's unchanged expected result, including where the external activity identifier is reused. Dispose of scratch and verify it against the inventory. Record each failed assertion, its actual disposition and the affected control. The separate [custody contract](p2-f-private-custody-contract.md) specifies the full drill.

**Closeout.** Record privately one row per object/location with prior presence, expected/observed state, verification method, role, time, deadline and any retest or pending backup expiry. If one copy is VERIFIED_DELETED and its backup remains protected, report both states. Recheck expiry and notify the participant of unresolved copies/limits under the agreed procedure. These checks establish bounded logical absence or restricted processing. They do not establish SSD block erasure, cryptographic destruction, absence of all possible forensic remnants or deletion outside inventoried custody. No staging machine or human record is certified by this template.
