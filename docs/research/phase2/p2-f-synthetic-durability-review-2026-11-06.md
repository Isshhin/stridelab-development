# P2-F synthetic durability review — 2026-11-06

Scope: research-only F2.2 journal at starting head `92e2ed968fa0418bb6738d402e31fd4465a069b6`. No human records, credentials, held-out outcomes or device inputs were used. This review and correction were made in the implementation session and are not an independent signed approval.

## Findings and disposition

1. **Duplicate membership and incomplete invalidation — corrected in projector 3.** Two distinct link events for one activity/opportunity caused projectors 1 and 2 to repeat the activity ID; after all links were revoked, one duplicate could remain. Projector 3 rebuilds membership from the surviving link set; both link identities are retained. Existing projectors are not silently changed and continue to return historical behavior.
2. **Uninterpreted generic supersession — quarantined, not implemented.** `supersedes_event_id` could refer to an earlier event while both remained effective. Projector 3 rejects a relevant view containing that field; a historical decision before the supersession remains readable, but current validity checks include later visible events. A fully typed supersession/descendant-invalidation model remains future work.
3. **Causal ordering — bounded fail-closed behavior.** Reference projectors 1 and 2 sort availability ties by event ID. Projector 3 quarantines equal availability in its relevant scope because database arrival order alone does not prove actor-side causality. This can reject unrelated events. It also quarantines a source correction or link revocation that is available no later than its referenced source/link, or is effective before it. These checks do not prove real provider clocks or all possible causal relationships.
4. **Backup destination overwrite — corrected.** The original backup API silently replaced an existing SQLite database. Exclusive creation now rejects an existing destination. A crash or authorization failure can still leave a partial newly created copy, and must be handled outside this prototype.
5. **Downstream lineage and historical projectors — limited.** The store can invalidate its own returned projection through `assert_current`, and source corrections conservatively retire the affected activity's links. It cannot recall a Python object already copied by a caller, enumerate or purge external descendants, or safely use v1/v2 counts with duplicate links. The current projection records invalidation IDs but does not pin a separate invalidation-set digest, current authority epoch or as-of time; the selected-event digest alone cannot independently reproduce current validity. No materialized-view or external-processor invalidation was demonstrated.
6. **Authority, storage and restore — private use blocked.** The SQLite file and backups are plaintext; `SyntheticAuthority` is an in-memory test double and its checks are not an atomic cross-process revocation barrier. The code accepts caller-supplied actor/view identity rather than authenticating a principal. Synthetic backup/reopen denial does not demonstrate real deletion, key destruction, backup expiry, late-import suppression or an independently controlled nonrollback authority.
