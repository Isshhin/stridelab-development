## What the rehearsal proves

**Synthetic verification on Windows.** With CPython 3.12.10 the filesystem drill returned `SYNTHETIC_REHEARSAL=PASS` and left zero entries in its scratch parent. The private command demonstration, `py -3.12 research/validation/test_p2_private_audit.py --synthetic-demo`, returned `PASS`. These are separate executions: the first challenges storage recovery, the second invokes the offline CLI with invented records and a precomputed reference. The demonstration requires a writable temporary location outside the source checkout. The local full research discovery command was `py -3.12 -m unittest discover -s research/validation -p "test_*.py" -v`. It ran 239 methods, with 238 passes and one skip because the sandbox could not create a Windows symlink. All 65 prior P2-F methods and ten new operational tests are included. Both baseline CI jobs passed all 229 original research methods. Results for this new operator commit are recorded separately on [PR #34](https://github.com/Isshhin/stridelab-development/pull/34).

The rehearsal stages two synthetic accounts, copies a generated original, decodes samples, links the performed activity to the delivered revision and compares against fixed expected measurements. It saves a pre-withdrawal snapshot, revokes one account in a separate SQLite register, removes scoped live files, and challenges a stale restore in a fresh process. The unrelated account remains usable. Passing these checks establishes logical processing controls for the tested code. It cannot establish disk encryption, user permissions, physical erasure, cache removal in a particular viewer, expiry at a backup provider, or resistance to rollback of the authority itself. Test those controls on the selected machine.
